# 采集引擎设计 — Claude Code 多线程调度

## 一、现有模式参考

驾驭工程中 `BatchRunner`（`electron/cli/batchRunner.ts`）已实现了以下成熟模式：

```typescript
// 并行模式核心（直接借鉴）
const promises = task.commands.map(async (item, index) => {
  if (signal.aborted) return null
  emit({ type: 'step_start', taskId: task.id, command: item.command, index })
  const t0 = Date.now()
  const result = await registry.execute(item.command, item.args, ctx)
  emit({ type: 'step_end', taskId: task.id, command: item.command, result, durationMs: Date.now() - t0, index })
  return { command: item.command, result, durationMs }
})
const settled = await Promise.all(promises)
```

采集引擎在此基础上扩展三个维度：
1. **进程管理**：registry.execute() → spawn('claude', [...]) 外部进程
2. **并发控制**：Promise.all → 进程池（限制同时运行数）
3. **断点续采**：进度持久化到磁盘

## 二、核心设计

### 2.1 ClaudeRunner — 单进程管理器

```typescript
// electron/collector/claudeRunner.ts

interface RunnerConfig {
  taskId: string
  prompt: string
  targetRepo: string
  workDir: string            // 临时工作目录
  timeout: number            // 120000 (2min)
  outputFormat: 'stream-json' | 'text'
}

interface RunnerEvent {
  type: 'start' | 'chunk' | 'yaml_block' | 'complete' | 'error' | 'timeout'
  taskId: string
  data?: any
  error?: string
}

class ClaudeRunner {
  private proc: ChildProcess | null = null
  private abortController: AbortController

  // 启动 Claude Code 进程
  async start(config: RunnerConfig, onEvent: (e: RunnerEvent) => void): Promise<void>

  // 中止
  abort(): void

  // 获取运行状态
  getState(): 'idle' | 'running' | 'done' | 'error'
}
```

#### start() 内部流程

```
1. 构建完整 prompt
   ┌─────────────────────────────────────────────
   │ {数据源提示词}
   │
   │ 输出要求：
   │ 每条数据输出一个独立 YAML frontmatter 块：
   │
   │ ---
   │ id: tang-li-bai
   │ name: 李白
   │ type: person
   │ category: 隋唐
   │ era: 唐朝
   │ year_start: 701
   │ year_end: 762
   │ summary: 唐代伟大的浪漫主义诗人...
   │ ---
   │
   │ {正文内容}
   │
   │ ═══════════════════════════════════
   │ （每个条目之间用分隔符）
   │ ═══════════════════════════════════
   └─────────────────────────────────────────────

2. spawn 进程
   const proc = spawn('claude', [
     '-p', prompt,
     '--output-format', 'stream-json',
     '--max-turns', '50',
     '--no-color',
   ], {
     cwd: workDir,
     stdio: ['pipe', 'pipe', 'pipe'],
     env: { ...process.env },
   })

3. 流式输出处理
   proc.stdout.on('data', (chunk: Buffer) => {
     // 解析 stream-json 或文本
     // 检测 YAML frontmatter 模式 /^---\n[\s\S]*?\n---/
     // 每匹配到一个完整块 → onEvent({ type: 'yaml_block', data: parsed })
   })

4. 进程退出
   proc.on('exit', (code) => {
     if (code === 0) onEvent({ type: 'complete' })
     else onEvent({ type: 'error', error: `exit code ${code}` })
   })
```

### 2.2 CollectorEngine — 多线程调度

```typescript
// electron/collector/collectorEngine.ts

interface CollectionTask {
  sourceId: string
  batches: Array<{
    batchId: number
    prompt: string         // 含分片参数（如"第1-10条"）
    targetRepo: string
  }>
  parallelism: number      // 允许同时运行的 Claude 进程数
  targetRepo: string
}

class CollectorEngine {
  private pool: Map<string, ClaudeRunner> = new Map()  // 活跃进程池
  private queue: CollectionTask[] = []                  // 等待队列
  private maxConcurrency: number = 4                    // 全局最大并发

  // 启动一个采集源
  async runSource(sourceId: string, onProgress: (e: ProgressEvent) => void): Promise<CollectResult>

  // 中止所有
  abortAll(): void
}
```

#### 进程池调度算法

```
runSource(sourceId)
    │
    ├─ 1. 加载 sourceConfig[sourceId]
    ├─ 2. 计算分片（totalItems / batchSize → N 个 batch）
    ├─ 3. 检查断点（collector-state.json → skip 已完成的 batch）
    ├─ 4. 构建 N 个 prompt（每个含分片偏移参数）
    │
    ├─ 5. 启动进程池
    │      activeSlots = min(parallelism, maxConcurrency)
    │      while (pending.length > 0 || pool.size > 0) {
    │        // 填充空闲槽位
    │        while (pool.size < activeSlots && pending.length > 0) {
    │          batch = pending.shift()
    │          runner = new ClaudeRunner()
    │          pool.set(batch.batchId, runner)
    │          runner.start(batch, onRunnerEvent)
    │        }
    │        // 等待任一进程完成
    │        await Promise.race([...pool].map(([id, r]) => r.waitForCompletion()))
    │        // 移除已完成进程，释放槽位
    │      }
    │
    └─ 6. 保存状态 → 返回统计
```

### 2.3 OutputParser — 输出解析

```typescript
// electron/collector/outputParser.ts

interface ParsedItem {
  frontmatter: Record<string, any>
  body: string
  raw: string
}

class OutputParser {
  // 从 Claude Code 流式输出中提取 YAML frontmatter 块
  extractYamlBlocks(streamOutput: string): ParsedItem[]

  // 校验单条数据是否符合目标仓库的 taxonomy 要求
  validateAgainstTaxonomy(item: ParsedItem, taxonomy: RepoTaxonomy): { valid: boolean; errors: string[] }

  // 将 ParsedItem 转为 pendingResourceStore 的 PendingResourceItem
  toPendingItem(item: ParsedItem, targetRepo: string, taxonomy: RepoTaxonomy): PendingResourceItem
}
```

#### 分隔符策略

每个 Claude Code 输出包含多条数据，分隔方式：

```
═══════════════════════════════════
（10 个等号以上为分隔符）
═══════════════════════════════════
```

或要求 Claude Code 输出 JSON Lines 格式：
```jsonl
{"id":"tang-li-bai","name":"李白",...}
{"id":"tang-du-fu","name":"杜甫",...}
```

## 三、并发控制

### 3.1 进程池上限

```
全局限制: maxConcurrency = min(cpuCores - 1, 6)   // 最多 6 个 Claude 进程
单源限制: sourceConfig.parallelism                  // 每个采集源独立上限
```

### 3.2 资源保护

| 保护项 | 策略 |
|--------|------|
| **内存** | 每个进程 stdout 缓冲上限 10MB，超则截断 |
| **磁盘** | 临时目录每个进程独立，完成后清理 |
| **API 限流** | Claude Code 内部已有重试，不做额外控制 |
| **死进程** | 超时 2min 自动 SIGTERM，再 10s 后 SIGKILL |

### 3.3 进程池状态机

```
                    ┌──────────┐
         启动 ────→ │  idle    │
                    └─────┬────┘
                          │ 有任务
                          ▼
                    ┌──────────┐
                    │ running  │──── 完成 ────→ done → 清理
                    └─────┬────┘
                          │
                    ┌─────┴─────┐
                    │  timeout  │ → SIGTERM → SIGKILL
                    │  error    │ → 记录 + 重试 1 次
                    │  abort    │ → 用户中止
                    └───────────┘
```

### 4.2 恢复策略

```typescript
async resumeSource(sourceId: string): Promise<CollectResult> {
  const state = loadState(sourceId)
  if (!state || state.runningBatch !== null) {
    // 上次异常退出，丢弃未完成的 batch，从断点继续
    const pending = batches.filter(b => !state.completedBatches.includes(b.batchId))
    return this.runRemaining(sourceId, pending)
  }
}
```

## 五、与工坊管线衔接

采集完成后的自动流转：

```
collectorEngine.runSource("xxx")
    │
    ├─ 每个 yaml_block → outputParser.validateAgainstTaxonomy()
    │                  → pendingResourceStore.addItem()
    │
    ├─ 全部 batch 完成
    │
    ├─ → pending:audit-all    (自动审核)
    │
    ├─ → contribution:commit-all (安全提交)
    │
    └─ → 返回 CollectResult { collected, audited, committed, pushed }
```

用户可选择：
- **全自动**：采集 → 审核 → 提交 → 推送（无人值守）
- **半自动**：采集 → 审核（人工确认）→ 提交
- **手动**：仅采集，后续手动操作

## 六、错误处理矩阵

| 位置 | 错误 | 处理 |
|------|------|------|
| ClaudeRunner.start() | 进程无法启动 | 重试 1 次 → 标记 batch 失败 |
| ClaudeRunner 运行中 | 超时 (2min) | SIGTERM → 等待 10s → SIGKILL |
| OutputParser | YAML 解析失败 | 跳过该条目 → 记录到 rejected.json |
| OutputParser | 必填字段缺失 | 跳过 → 记录到 rejected.json |
| pending:audit-all | 评分过低 (< 4) | 标记为 rejected |
| contribution:commit-all | 推送被拒 | pull --rebase 重试 1 次 |
