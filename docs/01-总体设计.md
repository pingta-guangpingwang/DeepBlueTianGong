# 深蓝天工 · 知识采集引擎 — 总体设计

## 一、项目定位

**深蓝天工（DeepBlue TianGong）** 是一个独立的 AI 知识采集、整理、审核、发布工具。

名字取自宋应星《天工开物》——中国古代最伟大的技术百科全书。天工，自然之力；开物，人造之器。AI 驱动采集为"天工"，人工审核标化为"开物"。

| 维度 | 驾驭工程（GodHarnessFarm） | 天工（TianGong） |
|------|---------------------------|-------------------|
| **定位** | 多项目管理 + AI 驾驶舱 | 多源数据采集 + 知识整理引擎 |
| **AI 调用** | AgentLoop 交互式（单线程） | Claude Code CLI 批量并行（多线程） |
| **产出** | 跨项目操作 | GitHub 标准化知识仓库 |
| **使用场景** | 开发者日常驾驭项目 | 知识工作者定期采集 + 发布 |
| **关系** | 消费端：拉取天工产出的仓库 | 生产端：生产标准化知识仓库 |

## 四、仓库配置系统（核心新增）

每个仓库自描述其分类法（taxonomy），引擎不再硬编码任何领域知识。

```json
// repos.json
{
  "version": "1.0",
  "repos": [
    {
      "name": "DeepBluePrompt",
      "label": "深蓝提示词库",
      "labelEn": "DeepBlue Prompt Library",
      "remote": "https://github.com/pingta-guangpingwang/DeepBluePrompt.git",
      "visible": true,
      "taxonomy": {
        "types": [
          { "id": "prompt", "label": "提示词", "dir": "prompts" }
        ],
        "categories": ["开发", "写作", "设计", "分析", "翻译", "教育"],
        "requiredFields": ["id", "name", "type", "category", "summary"],
        "optionalFields": ["subcategory", "tech_stack", "style_tags", "use_cases", "source_url"]
      }
    },
    {
      "name": "AIHistoryDynasty",
      "label": "AI历代王朝",
      "remote": "https://github.com/pingta-guangpingwang/AIHistoryDynasty.git",
      "visible": true,
      "taxonomy": {
        "types": [
          { "id": "dynasty",   "label": "朝代",   "dir": "dynasties" },
          { "id": "emperor",   "label": "帝王",   "dir": "emperors" },
          { "id": "event",     "label": "大事记",  "dir": "events" },
          { "id": "battle",    "label": "战役",   "dir": "battles" },
          { "id": "literature","label": "文献",   "dir": "literature" }
        ],
        "categories": ["先秦", "秦汉", "三国魏晋", "隋唐", "宋元", "明清", "近现代"],
        "requiredFields": ["id", "name", "type", "category", "era", "summary"],
        "optionalFields": ["year_start", "year_end", "location", "related_people", "predecessor", "successor", "source_url"]
      }
    }
  ]
}
```

引擎行为：
- 读取 `repos.json` → 遍历 `repos` 数组
- 每个 repo 的 `taxonomy.types` → 决定文件存放目录
- `taxonomy.requiredFields` → 决定 YAML 校验规则
- `taxonomy.categories` → 决定前端筛选选项
- `visible` → 决定前端是否展示

## 五、采集引擎（核心新增）

### 5.1 Claude Code CLI 多线程模型

```
采集任务配置
┌─────────────────────────────────────────────────────┐
│ {                                                    │
│   id: "baidu-history-dynasty",                      │
│   sourcePrompt: "从百度百科采集中国各朝代数据...",     │
│   targetRepo: "AIHistoryDynasty",                   │
│   parallelism: 3,        ← 同时开 3 个 Claude Code    │
│   batchSize: 10,         ← 每个线程处理 10 条         │
│   schedule: "0 3 * * 0"  ← cron 表达式               │
│ }                                                    │
└─────────────────────────────────────────────────────┘
```

### 5.2 Runner 生命周期

```
claudeRunner.start(task)
    │
    ├─ 1. 构建 prompt（注入数据源 + 目标 repo 配置）
    ├─ 2. spawn('claude', ['-p', prompt, '--output-format', 'stream-json'])
    ├─ 3. stream 解析 → outputParser.extractYamlBlocks()
    ├─ 4. 每个 YAML 块 → pending:add(targetRepo, parsedItem)
    ├─ 5. 进程退出 → 上报统计（成功/失败数）
    └─ 6. 所有 runner 完成 → 触发 audit-all + commit-all
```

### 5.3 并行控制

```
collectorEngine.run(sourceId)
    │
    ├─ 读取 sourceConfig
    ├─ 计算分片：总条目 / batchSize = N 个任务
    ├─ 启动 min(N, parallelism) 个 Claude Code 进程
    ├─ 每个进程执行 batchSize 条采集
    ├─ 进程池管理：一个完成 → 下一个启动（若还有任务）
    └─ 全部完成 → 进入审核管线
```

### 5.4 断点续采

```
采集状态持久化（collector-state.json）
{
  "sourceId": "baidu-history-dynasty",
  "lastRunAt": "2026-05-27T03:00:00Z",
  "completedBatches": [0, 1, 2],
  "pendingBatches": [3, 4, 5],
  "totalItems": 60,
  "collectedItems": 30
}
```

## 六、工坊管线（从驾驭工程提取）

### 6.1 提交流程（安全闸门完整保留）

```
Stage 1: pending:add        → 原始数据进入待审队列
Stage 2: pending:audit-all  → AI 自动审核 + 评分
Stage 3: YAML 标准化         → 生成标准 frontmatter + 正文
Stage 4: pending:approve-all → 写入本地仓库目录
Stage 5: validateCommitScope → 闸门1：仅新增文件 + YAML 校验
Stage 6: forcePullOrAbort   → 闸门2：强制拉取，失败中止
Stage 7: commitChanges      → 闸门3：精确提交（按文件列表 add）
Stage 8: safePushBranch     → 闸门4：推送 + non-fast-forward 自动 rebase 重试
```

### 6.2 错误处理

每个 Stage 失败时：
- 明确的中文错误信息
- 失败步骤标签（scope-check / pull / commit / push）
- 不跳过任何闸门
- 失败仓库不影响其他仓库继续处理

## 七、数据流完整示例

```
1. 用户配置采集源
   sourceConfig: { prompt: "采集唐朝历史人物...", targetRepo: "AIHistoryPeople" }

2. 定时触发（cron: "0 3 * * 0"）
   → collectorEngine.run("tang-people")

3. Claude Code 并行采集
   Runner#1: "李白, 杜甫, 白居易..."      → YAML × 10
   Runner#2: "王维, 孟浩然, 岑参..."      → YAML × 10
   Runner#3: "韩愈, 柳宗元, 刘禹锡..."    → YAML × 10

4. 数据汇聚
   → pendingResourceStore: 30 条待审

5. AI 审核
   → audit-all: 自动评分 (5-10分)
   → 过滤低分 (< 4分)

6. 提交 GitHub
   → commitChanges → push → PR（可选）

7. 下游消费
   驾驭工程 / AI历史书网站: git pull → 渲染展示
```

## 九、与驾驭工程的关系

```
驾驭工程（GodHarnessFarm）              天工（TianGong）
┌─────────────────────────┐           ┌─────────────────────────┐
│ 驾驭智能 AgentLoop        │           │ Claude Code × N 并行采集  │
│ 多项目管理                │           │ 数据源管理                │
│ 角色系统                  │           │ 采集调度                  │
│ 会话管理                  │           │ 工坊管线（审核→提交）      │
│ 插件系统                  │           │ 仓库配置                  │
│ 工作流引擎                │           │                          │
├─────────────────────────┤           ├─────────────────────────┤
│ 资源工坊（消费端）         │── git pull ─→│ 资源工坊（生产端）         │
│  搜索/浏览/查询            │           │  搜索/审核/标准化/提交     │
└─────────────────────────┘           └─────────────────────────┘
```

天工提交到 GitHub → 驾驭工程 git pull 同步 → 用户在驾驭工程搜索浏览。
两边共享 `resourceStore` 的核心逻辑，但上层使用方式不同。
